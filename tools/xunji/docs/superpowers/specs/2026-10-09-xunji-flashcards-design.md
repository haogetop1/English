# Xunji Android 闪卡工具设计

日期：2026-10-09。

状态：用户已确认路线、首版功能、视觉方向及本文正式设计；实现计划待审阅。尚未开始产品实现、依赖安装或 APK 构建。

## 1. 目标与约束

开发一款可安装的 Android 闪卡应用，供用户自己制卡并通过间隔复习记忆内容。结合此前英语学习需求，示例内容使用英语词汇与例句，但应用支持任意文本正面与背面。

已确认采用自建原生界面、复用 FSRS 算法的路线；第一版独立使用，数据保存在手机本地。应用的工作名称为 Xunji，界面显示“寻记”。

当前工作目录为 `/workspace/English/tools/xunji`。后续源码、文档、工具链下载、缓存、构建输出和截图均位于该目录内；既有调研文档保留原位置，不移动或覆盖用户文件。

首版成功标准：用户能创建牌组和卡片，完成显示答案与评分的复习流程，评分影响下一次到期时间；应用重启后保存内容和学习记录；能够导出并恢复本地备份；产出经过构建验证的 Android APK。

第一版不包含 Anki `.apkg` 导入、AnkiWeb 同步、账户、AI 制卡、复杂 HTML 模板、图片附件、录音或系统朗读。应用不申请联网权限。不会把独立实现称为 Anki 官方客户端或兼容客户端。

## 2. 平台和工程结构

- Android 原生应用，最低支持 Android 8.0 / API 26。
- Kotlin、Jetpack Compose、Material 3；界面默认中文。
- Room 存储业务数据；设置与数据一起备份。
- 使用 Kotlin Coroutines、Flow 和 ViewModel 管理异步操作与界面状态。
- FSRS 固定候选依赖为 `io.github.open-spaced-repetition:fsrs:1.0.0`，MIT 许可。
- JVM 源码目标为 Java 17；Android 工程启用必要的反糖化支持。
- Gradle Wrapper、Android SDK 和依赖使用明确、相互兼容的正式版本；由实现计划列出具体版本，不使用动态版本或开发分支。

工程分为两个 Gradle 模块，避免一次建立大量模块：

| 模块 | 职责 | 依赖边界 |
| --- | --- | --- |
| `core` | 调度接口、FSRS 适配、队列规则、业务数据模型与时间逻辑 | Kotlin/JVM、FSRS；不依赖 Android UI 或 Room |
| `app` | Android UI、ViewModel、Room、业务操作、备份与文件选择 | 依赖 core；UI 通过业务操作访问数据 |

源码工程放在 `android/` 下。工具链放在 `.toolchain/`，Gradle 与 Android 用户缓存放在项目内独立忽略目录；可交付 APK 和验证记录放在 `artifacts/`。需要的工具链初始化命令写入项目文档，不假定宿主已有 Android SDK。

不创建额外 Git worktree，不推送、不发布商店版本。开发验证使用独立 debug applicationId 和 debug 签名。最终交付说明须区分可安装的 debug APK 与正式发布签名 APK。

## 3. 页面与导航

主导航为“今日”“牌组”“记录”，设置由顶栏入口进入。制卡和复习作为独立页面进入，返回后刷新对应数据。

### 3.1 今日

顶部显示日期与简短问候；主要区域显示到期卡片数、今日可学习新卡数、今日评分次数和已学习的新卡数。

“开始复习”启动全部牌组的学习队列。首屏空状态引导创建牌组和第一张卡，不默认插入演示数据。演示内容只用于测试或设计截图。

到期数不包含从未学习的新卡。可学习新卡数受每日新卡上限约束；新卡上限不限制已到期复习。

不要求连续打卡，不以漏学一天显示失败状态，也不自动清除积压到期卡。用户可以在预留的缓冲日补学。

### 3.2 牌组与卡片列表

牌组列表显示名称、总卡数、待复习数和新卡数。支持创建、重命名和删除。名称去除首尾空白后长度为 1～80 字符，允许不同牌组同名，内部以 ID 区分。

牌组详情显示卡片列表、正面内容摘要、新卡/学习中/待复习状态，并提供新增、编辑、删除和在当前牌组复习入口。

删除牌组需说明将同时删除其中卡片和学习记录，确认后在一个事务内执行。删除卡片也需确认。当前正在复习的卡片被删除后，队列重新读取，不提交陈旧评分。

### 3.3 制卡

正面和背面为必填多行文本，支持可选的例句字段。正面最大 2,000 字符、背面最大 10,000 字符、例句最大 4,000 字符；必填字段不能仅包含空白。

推荐用法：正面填英语词汇或问题，背面填释义或答案，例句填上下文。例句只在答案面显示，不另外创建复习卡。

保存按钮有提交中状态，防止重复插入。验证失败时保留输入并在对应字段显示中文错误。离开有未保存修改的页面时提示继续编辑或放弃。

编辑内容保留既有调度状态与学习记录；新建卡片进入“新卡”状态。第一版每条内容只生成一张正面→背面的卡片。

### 3.4 复习

正面阶段展示牌组名、卡片内容和“显示答案”按钮；例句、背面和评分按钮不可见。

显示答案后展示背面、可选例句和四档评分按钮：

| 按钮 | FSRS 评分 | 含义 |
| --- | --- | --- |
| 忘记 | AGAIN / 1 | 未能回忆 |
| 困难 | HARD / 2 | 能回忆，但很费力 |
| 记得 | GOOD / 3 | 能正常回忆 |
| 轻松 | EASY / 4 | 很容易回忆 |

每个评分按钮显示预计下次间隔。分钟、小时、天按易读单位展示，实际到期时间按算法保存。预览不写入数据库，不改变卡片状态。

评分后更新下一张，显示短暂的“已记录”反馈，并提供撤销最近一次评分入口。提交中禁用评分按钮；提交失败时保留当前卡片和答案，允许再次提交。

退出复习时保留已提交评分，不把未评分卡片计入完成。设备旋转保持当前卡片和答案展示状态；进程重启后从已保存的调度状态重新生成队列，未提交答案不自动算作复习。

当前没有可学习卡片时显示已提交评分数、学习卡片数和本次有效用时；如还有尚未到期的学习步骤，显示最近到期时间，不宣称所有卡片已掌握。

### 3.5 记录

展示今日和最近 7 个本地日的评分次数、学习卡片数、忘记比例和有效复习用时。评分次数可能大于卡片数，两个指标分开展示。

“忘记比例”定义为 AGAIN 次数 / 有效评分总数，不称为客观记忆率。零记录时显示空状态，不进行除零计算。被撤销的评分不参与统计。

### 3.6 设置和备份

每日新卡上限默认 20，可设为 0～100；0 表示暂不学习新卡，不暂停到期复习。上限为所有牌组合计，按用户当前时区的日期计算。

主题支持跟随系统、浅色、深色。备份入口提供导出和恢复功能，采用应用自己的 JSON 格式，清楚说明不是 Anki 牌组格式。

## 4. 视觉与可访问性

采用安静、清晰、适合长时间阅读的视觉风格。浅色主题建议：背景 `#F7F5EF`，主要表面 `#FFFFFF`，主色 `#24584A`，正文 `#202B26`，次要文字 `#5A665F`，琥珀强调 `#B77924`。深色主题使用深绿色灰背景、浅色正文和较亮绿色强调，不直接反转浅色颜色。

主标题约 28 sp，页面标题 22 sp，卡片正面 28～36 sp，正文 16～18 sp。使用系统字体，英语正文适当增加行距；不依赖在线字体或远端图片。

页面边距 20～24 dp，区块间距 16～24 dp，卡片圆角 20～24 dp。顶栏、底部导航、卡片和按钮共用统一设计 token，避免页面各自采用不同风格。

复习卡片采用内容淡入或轻量位移动画，约 180～240 ms，不使用持续装饰动画。尊重系统动画设置；不通过只有颜色的方式区分评分或错误。

支持大字体、长文本滚动、软键盘避让和窄屏。关键点击区域至少 48 dp；图标有可访问名称，TalkBack 可识别显示答案及各档评分。实际渲染阶段检查文字对比度，正文目标至少 4.5:1。

复习按钮在常规宽度使用四列；大字体或窄屏可变为两列，不能截断标签或间隔文字。暗色、空状态、输入错误、加载及完成状态采用同一设计系统。

## 5. 数据模型

Room 数据库初始 schemaVersion 为 1。业务 ID 使用 UUID 字符串；算法对象的 cardId 不作为业务主键，适配器独立映射结果。

| 实体 | 核心字段与规则 |
| --- | --- |
| Deck | id、name、createdAt、updatedAt |
| Card | id、deckId、front、back、example、createdAt、updatedAt |
| CardSchedule | cardId、phase、step、stability、difficulty、dueAt、lastReviewAt、firstReviewedAt、revision |
| ReviewLog | id、cardId、deckId、sessionId、rating、reviewedAt、durationMs、beforeSchedule、afterSchedule、undoneAt |
| AppSettings | 单行设置：newCardsPerDay、themeMode、schemaVersion |

CardSchedule 与 Card 一对一，外键删除时级联；ReviewLog 保留同一次评分的前后状态以支持撤销。第一版硬删除卡片及相关记录；删除界面明确提示这个影响。

phase 为 NEW、LEARNING、REVIEW、RELEARNING。java-fsrs 没有独立 NEW 枚举，因此 NEW 是应用层状态，firstReviewedAt 为空；首次评分后转换为库返回状态。新卡 dueAt 为创建时刻，但队列单独分类，不能计入到期复习数。

所有时间存储为 UTC epoch milliseconds，计算传入 Instant；展示和每日上限转换到设备时区。时间源使用可注入 Clock，便于测试跨天与到期逻辑。

revision 每次评分或撤销递增。应用自己存储调度字段，不依赖第三方库 JSON 格式作为数据库或备份格式。

## 6. 间隔复习与队列

### 6.1 调度接口

core 定义独立 Scheduler 接口：以当前卡片调度快照、评分和评估时间生成新调度状态及评分结果，并提供四档间隔预览。FSRS 实现只负责计算，不访问 Room、不操作 UI。

首版固定使用 java-fsrs 1.0.0 默认 FSRS 参数，desiredRetention 为 0.9，学习步骤为 1 分钟和 10 分钟，重新学习步骤为 10 分钟。关闭 fuzzing，保证同一输入和时间的预览与提交计算一致。首版不开放参数优化与高级算法设置。

实际评分时间取点击评分按钮的时间。展示间隔是估计值，提交时按真实点击时间重新计算；测试中使用相同注入时间检查预览与结果一致。应用从后台恢复时刷新预览。

库的 Java 17 字节码、record、java.time 和运行时依赖必须通过 Android 构建与设备测试验证；如果兼容验证失败，应修复工具链或支持配置，不悄悄换成固定间隔或其它算法。

### 6.2 取卡规则

队列可限定一个牌组或包含全部牌组。每次取卡重新检查数据库，顺序为：

1. 到期的 LEARNING、RELEARNING 卡，按 dueAt、id 排序。
2. 到期的 REVIEW 卡，按 dueAt、id 排序。
3. 每日新卡额度内的 NEW 卡，按 createdAt、id 排序。

学习步骤未到期时不提前重复展示卡片。还有其它可学习卡片时继续；全部没有可学习卡片时显示完成或等待状态。UI 不为等待学习步骤保持后台定时进程。

当日已学新卡数为 firstReviewedAt 落在当前本地日的卡片数。再次复习同一新卡不再次消耗额度。牌组删除会自然更新这一统计；撤销首次评分会恢复 NEW 并返还额度。

缺课后保留所有 dueAt，不批量重置，不把积压自动标为已学。切换时区只改变本地日统计边界，不改变卡片 UTC 到期时间。

## 7. 评分、撤销与并发

评分事务执行以下步骤：检查卡片仍存在、revision 与展示快照一致；检查该提交操作 ID 尚未写入；计算新状态；保存 CardSchedule 和 ReviewLog；提交后更新 UI。操作 ID 有唯一约束，重试不能造成两次记录。

新状态、首次学习时间和日志必须在同一 Room 事务内更新。过期 revision 不强制覆盖较新状态，而是刷新当前卡片并提示状态已变化。

撤销仅针对当前会话最后一次有效评分。检查数据库仍处于该日志的 afterSchedule 所对应 revision，事务内恢复 beforeSchedule、递增 revision、标记 undoneAt。撤销后重新显示该卡片正面；被撤销日志不计入统计。

一次撤销后入口关闭，不继续撤销更早记录；再次完成评分后可撤销新的最后一次评分。离开复习页面后结束会话，第一版不跨会话提供撤销。备份包含有效和已撤销日志，但不恢复正在显示的页面或活动会话。

有效复习用时只累计页面前台时间；从显示正面到评分的时间不超过单次 5 分钟，上限用于避免长时间闲置夸大统计。设备锁屏和进入后台暂停计时。

## 8. 备份与恢复

导出使用 Android Storage Access Framework，由用户选择文件位置；应用不申请所有文件访问权限。扩展名建议 `.xunji.json`。

格式包含 format=`xunji-backup`、schemaVersion=1、exportedAt、decks、cards、schedules、reviewLogs、settings。使用稳定的业务 ID 和调度字段，不导出设备路径、运行时工具配置或 APK 签名信息。

导出在一致的数据快照上生成文件。失败时报告失败，不把不完整文件称为成功备份。

恢复只支持全量替换，不做隐式合并。读取并验证完成后，显示牌组、卡片和记录数量及替换说明，用户确认才写入。

输入文件上限 50 MiB；超过上限、格式错误、未知版本、重复 ID、失效外键、非法评分/状态、非有限数值、必填字段为空或超长、非法时间戳均拒绝。时间戳允许范围为 0 到 253402300799999 毫秒（UTC 年份不超过 9999）；评分用时为 0～300,000 毫秒。已有记忆参数的卡片 stability 不小于 0.001、difficulty 在 1～10 范围内；NEW 状态允许这两个字段为空。首版不接受高于 schemaVersion 1 的备份。

恢复写入在单个事务内进行，失败回滚并保留现有数据。成功后结束活动会话、刷新所有页面和主题设置。恢复后的学习队列保持备份中的到期时间，不把已学卡重置为新卡。

## 9. 错误处理

界面为首次使用、空牌组、今日无卡、无统计记录提供独立空状态。用户输入错误靠近对应字段显示；数据库、文件读写和调度异常显示可理解的中文反馈，不向用户展示内部堆栈。

数据库 schema 将来升级必须提供显式迁移，不能启用破坏性迁移回退。测试中可清空独立测试数据库，不影响用户数据。

在 App 初始化失败时显示错误和重试入口，不自动删除数据库。备份取消文件选择不视为失败。

## 10. 验收与验证

### 自动化验证

| 范围 | 必须证明的行为 |
| --- | --- |
| FSRS 适配 | 四档评分可计算；固定输入/时间结果确定；预览无持久化副作用；遗忘触发正确重新学习状态 |
| 取卡 | 到期学习优先、到期复习次之、新卡受额度控制；未到期卡不提前出现；额度为 0 仍能复习 |
| 时间 | UTC 到期判断、午夜额度切换、设备时区变化、不重复消耗新卡额度 |
| Room | 评分状态与日志原子保存；重复提交幂等；过期 revision 不覆盖；重启后数据存在 |
| 撤销 | 恢复完整快照、返还首次学习额度、统计排除撤销记录、防止撤销失效状态 |
| 备份 | 有效备份往返后数据等价；错误文件、版本或关系失败时原数据库不变 |
| Compose | 创建牌组→制卡→显示答案→评分→下一张→完成；验证必填输入、空状态和关键导航 |

测试应使用真实核心调度与数据库操作，不能仅断言常量、空测试运行或用固定间隔替代 FSRS。业务测试注入时间源，不靠长时间 sleep。

### 构建与设备验证

- 完成 Kotlin 编译、相关单元测试、Android lint 和 debug APK 构建。
- 检查 APK 包信息、最低 Android 版本和签名验证输出；检查不存在联网或广泛存储权限。
- 在可用的 Android 模拟器或设备上运行代表性 UI 与持久化验证，检查 Java-FSRS 的实际 Android 运行兼容性。
- 检查浅色、深色、长文本和大字体的实际渲染截图与可访问性。
- 仅 JVM 测试或 APK 构建成功不能替代设备验证。若当前云环境不能运行模拟器，应明确列出未执行的设备检查，并提供可安装 APK 和真机验收步骤；不能宣称设备流程已经通过。

### 交付

交付源码、README、可复用工具链与构建步骤、依赖许可证说明、实际构建的 debug APK、测试结果和可用时的设备截图。README 给出首次创建卡片、评分含义、备份恢复和首次安装方法。

实现计划按工具链与算法兼容验证、核心逻辑、持久化和备份、UI、完整验证拆分。每阶段完成后依据实际验证结果继续，不扩大到尚未确认的云服务或媒体功能。

## 11. 调研证据与当前限制

原始路线调研：[Android 闪卡路线比较](../../../../docs/research/2026-10-09-android-flashcards-options.md)。该调研记录保留撰写时的待确认状态，当前已确认需求以本文为准。
